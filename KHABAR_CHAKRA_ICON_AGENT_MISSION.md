## 0. ROLE AND AUTHORITY

You are a senior brand-systems engineer and vector designer working inside the **Khabar Chakra** repository (Next.js 16 App Router, TypeScript strict, Tailwind, `[locale]` routing for en/bn/hi, Supabase, Vercel Hobby).

You have **full autonomy** to read the repo, write files, run scripts, install **dev** dependencies, start the dev server and use the browser to verify. You must **finish the entire mission without asking the user anything**. When something is ambiguous, pick the most reasonable option, and record it in `docs/branding/ICON_DECISIONS.md`.

### Hard rules
1. **Vector first.** The master is hand-authored SVG (paths and shapes only). Every PNG/ICO is *rendered from the SVG by script*. Never hand-edit rasters. Never use AI image generation for production assets (it may be used only for optional mood exploration in Phase 1, and its output is never shipped).
2. **No text in any icon.** No letters, numbers, Bengali/Hindi/English words, tagline. Never put "খাবার চক্র", "KHABAR CHAKRA", "खाद्य चक्र" or "Save • Share • Sustain" inside an icon.
3. **One symbol, many outputs.** Never redesign between platforms. Same bowl, same arrow geometry, same leaves, same proportions.
4. **Do not touch unrelated code**, business logic, database, auth, or `docs/` files other than those listed in this mission.
5. **No secrets** in files, logs or commits. Do not add real emails, keys or admin details anywhere.
6. **No network assumption.** Prefer tools already in `node_modules`. If you must add a package, add it as a `devDependency` and record the exact installed version in `docs/VERSIONS.md`.
7. **Do not commit or push** unless the user's repo workflow already requires it. Leave changes in the working tree.
8. Stay within **free tools only** (consistent with the project's all-free stack).

## 1. PROJECT CONTEXT (read, don't ask)

- **App:** community food-lifecycle platform. Tagline: *Save • Share • Sustain*.
- **Lifecycle:** Buy → Track → Store → Consume → Cook → Share → Donate → Reuse → Recycle → Dispose responsibly.
- **Region/identity:** West Bengal first (Asansol), designed for all India. Identity must be **subtle and modern**, not ornamental. No flags, no religious symbols.
- **Palette:** the project design system is called **"Market Fresh"**. Before choosing any colour, **read `docs/DESIGN SYSTEM*` and `src/styles/`** and extract the real tokens. Use those hex values. Only if a token is missing, use the fallback palette in §4.
- **Public assets:** `public/` holds icons, 3D models and illustrations.
- **Interception file** in Next.js 16 is **`proxy.ts`** (not `middleware.ts`).
- **PWA/push:** web push exists (VAPID, service worker). iOS web push only works from Home Screen, so the Apple touch icon matters.
- **Existing logo:** the project already has a logo (bowl, vegetables, leaves, circular arrows, plus Bengali/English/Hindi text). Search the repo (`public/`, `public/branding/`, `docs/`, `src/assets`, any `logo*`) and **view it** as the visual reference. The app icon must feel like the same brand but **much simpler**.

## 3. PHASED EXECUTION PLAN

### PHASE 1 — Concept lock (fast, no waiting on the user)
Pick **one** direction and commit. Default decision (use unless the logo clearly contradicts it):

> **Bowl + two-arrow circular loop + two leaves + three tiny food shapes (tomato, orange/carrot, golden).**
> Deep teal bowl and loop, fresh-green leaves, food colours only as small accents. Friendly and trustworthy, **not** cartoonish, **not** a generic recycling/garbage symbol.

Optional exploration: you may use the **Prompt Bank (§9)** with an image-generation tool to sanity-check mood, but production art is the SVG in Phase 2. Do not block on this.

### PHASE 2 — Author the SVG master
Create `public/icons/src/` and author these files (viewBox `0 0 1024 1024`, no raster, no text, no external fonts, no filters/blur/shadows/gradients):

| File | Purpose |
|------|---------|
| `symbol-full.svg` | Transparent background, full symbol (bowl, food, loop, leaves) |
| `symbol-small.svg` | **Simplified** for ≤ 48 px: no food circles, thicker strokes, one big leaf |
| `icon-background.svg` | Solid brand background (light warm-neutral) |
| `icon-background-dark.svg` | Solid dark teal/near-black background |
| `icon-foreground.svg` | Same as `symbol-full` (Android adaptive foreground) |
| `icon-monochrome.svg` | Single colour (`currentColor`), uses negative space, no accents |

**Geometry rules (mandatory):**
- Centre = (512, 512). **All artwork must sit within a circle of radius ≤ 392 px** from centre (so a ×0.9 scale for maskable fits inside the 80 % safe circle, radius 409.6 at 1024).
- Minimum stroke/feature thickness in `symbol-full`: 40 px (so it survives down-scaling). In `symbol-small`: 64 px.
- Loop = **two clockwise arcs with round caps and triangular arrowheads, with two visible gaps** (reads as "cycle", not as a closed ring).
- Bowl = wide, friendly half-ellipse with a slightly overhanging rim. Food peeks above the rim. Leaves emerge from the top centre.
- Use rounded joins everywhere. No sharp thin spikes.

**Reference starter geometry** (you may refine proportions for beauty, but keep the structure and the safe-radius rule). Treat this as a working draft for `symbol-full.svg`:

Iterate until it looks professional: balanced negative space, optical centring, no cramped overlaps between arrowheads and leaves. Fix anything that looks off. Replace placeholder hexes with real Market Fresh tokens from Phase 0.

**Colour rules:** teal/green dominate (≥ 75 % of coloured area). Food colours are accents only. No neon. Contrast of the symbol against its background must be ≥ 3:1 for all non-accent parts.

### PHASE 3 — Build the generator script
Create `scripts/generate-icons.mjs` and add `"icons:build": "node scripts/generate-icons.mjs"` to `package.json`. The script must be **deterministic and idempotent** and:

1. Read SVGs from `public/icons/src/`.
2. Render with `sharp` (high `density` so edges are crisp) and write to `public/icons/`:

| Output | Size | Source / rule |
|--------|------|---------------|
| `favicon-16.png`, `favicon-32.png`, `favicon-48.png` | 16 / 32 / 48 | `symbol-small` on transparent |
| `favicon.ico` | 16+32+48 multi-size | Build ICO from the three PNGs (use `png-to-ico` devDependency, or write the ICO container by hand if offline). Also copy to `src/app/favicon.ico` if the project uses that convention |
| `favicon.svg` | vector | `symbol-small`, optionally with a `prefers-color-scheme` style so it stays visible on dark tabs |
| `icon-192.png`, `icon-512.png` | 192 / 512 | `symbol-full` composited on `icon-background` (full-bleed square, **no** rounded corners baked in) |
| `icon-192-maskable.png`, `icon-512-maskable.png` | 192 / 512 | Background full-bleed + foreground scaled **×0.9** and centred |
| `apple-touch-icon.png` | 180 | **Opaque** background, full-bleed square, no transparency, no baked corners |
| `icon-1024.png` | 1024 | Master raster for store/marketing use |
| `icon-monochrome.svg` | vector | from source |
| `icon-background.svg`, `icon-foreground.svg` | vector | copied from source |
| `badge-96.png` | 96 | **Notification badge:** white silhouette on transparent, from `icon-monochrome` simplified, no colour reliance |
| `icon-192-dark.png`, `icon-512-dark.png` | 192 / 512 | `symbol-full` on `icon-background-dark` |

3. Copy/refresh `public/branding/splash-logo.svg` from `symbol-full.svg`. **Do not overwrite** any existing `khabar-chakra-logo*.svg/png` files.
4. **Self-validate and fail loudly** (non-zero exit) if:
   - any maskable output has non-transparent artwork pixels farther than **0.40 × size** from centre (compute from the *foreground only* render before compositing);
   - any expected output is missing or has the wrong dimensions;
   - `apple-touch-icon.png` has an alpha channel with transparency;
   - any source SVG contains `<text`, `<image`, `<filter`, `<foreignObject`, or `data:image`;
   - the symbol-small render at 16 px has fewer than 2 distinct visually separated regions (use a simple connected-components or pixel-variance check) — i.e. it collapsed into a blob.
5. Print a clear summary table of what was generated.

### PHASE 4 — Wire into Next.js 16

1. **Web manifest:** create or update `src/app/manifest.ts` (Next.js `MetadataRoute.Manifest`):
   - `name: "Khabar Chakra"`, `short_name: "Khabar Chakra"` (if the project has an i18n manifest strategy, keep English here), `description` from the README tagline, `start_url: "/"`, `display: "standalone"`, `orientation: "portrait"`.
   - `theme_color` and `background_color` from Market Fresh tokens.
   - `icons`: 192 and 512 with `purpose: "any"`, 192 and 512 maskable with `purpose: "maskable"` (**separate entries; never `"any maskable"`**), SVG icon if appropriate.
2. **Metadata:** in the root layout's `metadata`/`viewport` export, set `icons` (favicon.ico, favicon.svg, favicon-32 png, apple-touch-icon), `themeColor` per light/dark scheme via `viewport`, and `appleWebApp` (title, `capable: true`, `statusBarStyle`). Respect the existing `[locale]` structure; icons are root-level so do **not** put them under a locale prefix.
3. **`proxy.ts`:** open the matcher. Confirm it **excludes** `/icons`, `/branding`, `/social`, `/favicon.ico`, `/manifest.webmanifest`, service-worker file, and `_next`. If not excluded, fix the matcher minimally and note it in the decisions log. Locale redirection must never hit these paths.
4. **Service worker / Web Push:** find where notifications are shown (`showNotification`, push handler). Set `icon: "/icons/icon-192.png"` and `badge: "/icons/badge-96.png"`. Do not change any other push logic.
5. **Other references:** grep the repo for old icon paths (`favicon`, `apple-touch`, `logo`, `icon-`) in code, emails templates and docs, and update only those that should point to the new system. Leave the full text logo alone.
6. **Optional (do it if cheap, skip if risky):** create `src/app/opengraph-image` or a static `public/social/og-image.png` from the symbol on a brand background. **Text is allowed in the OG image only if the existing logo asset can be reused as-is**; otherwise render symbol-only and note it.

### PHASE 5 — Verification (must actually run these)

1. `npm run icons:build` → must exit 0 and print the summary.
2. `npm run lint`, `npm run typecheck`, `npm run build` → must pass. Fix any issue you introduced. If a failure pre-existed, record it and don't "fix" unrelated code.
3. If scripts exist: `npm run check:contrast`.
4. **QA contact sheet:** generate `docs/branding/icon-qa.html` (self-contained, inline-embedded or relative `../../public/icons/...` images) showing every output at 16, 32, 48, 64, 128, 192, 512 px on light, dark, and mid-tone backgrounds, plus the maskable icon under **circle, squircle, rounded-square and teardrop** masks (CSS `clip-path`/`border-radius`) with the safe circle outlined, plus the notification badge on a dark status-bar strip.
5. **Browser check (use the Antigravity browser):** start `npm run dev`, open `http://localhost:3000`, and confirm:
   - the favicon appears in the tab area/head links resolve with HTTP 200;
   - `/manifest.webmanifest` returns valid JSON with all icon URLs returning 200 and correct `image/png` sizes;
   - `/en`, `/bn` and `/hi` all load without the icons being redirected;
   - no console errors related to icons or manifest.
   Take screenshots of the contact sheet and of the page head/Application → Manifest panel as artifacts.
6. **Visual self-review:** look at the 16 px and 32 px renders and the 1024 master with your own eyes (view the images). If the symbol is muddy at 16 px, simplify `symbol-small` further (thicker strokes, drop leaf detail) and rebuild. Repeat until clean. Do this loop at least once.

## 7. FAILURE HANDLING

- **`sharp` unavailable and no network:** write a minimal renderer using any rasteriser already in `node_modules` (e.g. `@resvg/resvg-js`, `canvas`), or use the Antigravity browser to render SVG → canvas → PNG with a small Node/Playwright script (Playwright is already a project dev dependency). Log the choice.
- **ICO packaging unavailable:** write the ICO container manually (header + directory + embedded PNGs).
- **Existing logo not found:** build from the README description (bowl, vegetables, leaves, circular arrows) and note it.
- **Symbol looks amateur after review:** iterate on proportions (arrowhead size, gap width, leaf angle, bowl depth) — up to 5 refinement passes — before accepting.
- **Pre-existing build/lint failures:** document; do not expand scope to fix them.
- **Never** stop to ask the user. Decide, log, continue.

## 8. BRAND RULES FOR EVERY FUTURE ICON (copy into `ICON_SYSTEM.md`)

1. Recognisable without text.
2. The food-cycle concept stays visible.
3. Positive and sustainable in feeling — never garbage/pollution imagery.
4. Green/teal stays the dominant identity.
5. Food colours are accents only.
6. Avoid excessive detail; nothing that vanishes at 32 px.
7. Same bowl / cycle / leaf language across all platforms.
8. Preserve safe space for adaptive/maskable masks.
9. Never put the full brand name inside a small app icon.
10. Do not invent separate icon styles per platform.

## 9. PROMPT BANK (optional mood exploration only — production = SVG)

**Master prompt**
> Professional modern app icon for "Khabar Chakra", a food-lifecycle and food-waste-reduction platform. A friendly bowl filled with fresh vegetables, surrounded by a smooth circular cycle formed by two curved arrows with clear gaps, plus two small fresh green leaves. Deep teal and natural leaf green dominate; tiny tomato-red, carrot-orange and golden-yellow food accents. Flat vector style, rounded geometry, strong silhouette, minimal detail, centred, generous safe area, readable at 32×32, light warm-neutral background. No text, letters, numbers or tagline.

**Negative prompt**
> text, letters, words, numbers, slogans, watermark, signature, photograph, photorealism, 3D render, heavy gradients, drop shadows, clutter, thin fragile lines, tiny vegetables, complicated recycling symbol, garbage bin, pollution imagery, sad tone, generic globe, flags, religious symbols, random cultural ornaments, mockups, device frames.

**Variant modifiers (append to master prompt when exploring)**
- *Minimal:* only bowl + loop + one leaf, readable at 32 px.
- *Community:* add 2–3 abstract connected dots/shapes around the bowl (no realistic people).
- *NGO/trust:* more geometric, less playful, no facial expression.
- *Youth/friendly:* very subtle friendly curve on the bowl rim; still not cartoonish.
- *Indian/Bengali identity:* subtle only — e.g. a rounder bowl form and a fresh green chilli or leafy-green accent; no ornament, flags or religious symbols.
